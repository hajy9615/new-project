# LEAD QUEST — 원장실로 가는 길

교육행정학 리더십론 수업용 학습 웹앱. 학생은 '예비교사'로 출발해 5개 월드(리더십의 개념 → 특성이론 → 행동이론 → 상황이론 → 최근 교육리더십론)를 통과하며 '원장'까지 승진함.

- 파일 하나(`index.html`)로 동작. 서버·로그인·설치 불필요.
- 학습 기록은 학생 각자의 브라우저(localStorage)에 저장됨.
- 반 리그·학습 분석은 '성과 코드'(학생 → 교수자)와 '리그 스냅샷 코드'(교수자 → 학생)로 집계함.

## 1. 기능 구성

| 구분 | 기능 |
|---|---|
| 학생 | 퀘스트 맵(월드 해금), 개념 카드(자기평정·간격 반복·내 말로 설명하기), 소크라테스 문답(5단계 질문 사슬·힌트 사다리·이해 수준 루브릭), 퀴즈 아레나(OX·4지선다·매칭·사분면 배치·관리망 좌표·분류·순서 배열, 확신도 채점), 사례 랩 6건, 보스전(8분·70점 통과), 하브루타 질문 카드, 출구 성찰, 오답노트·오개념 레이더, 리더십 연대기, 나의 리더십 스타일 자기점검, XP·직급 6단계·배지 16종, 오늘의 미션, 스트릭(주 1회 보호권), 성장 리그 |
| 교수자 | 학습 분석 대시보드(성과 코드 일괄 붙여넣기, 개념 숙달도 히트맵, 오개념 Top 5, 출구 성찰 키워드, 7일 미접속 조기 경보, 팀·성장 리그, CSV 내보내기, 리그 스냅샷 코드 생성), 라이브 전광판(라이브 퀴즈 + Peer Instruction 재투표, 팀 점수판, 워드클라우드, 하브루타 타이머) |

교수자 도구 진입: 앱 하단 `나` 탭 → `교수자 도구`.

## 2. 배포(학생 공유)

GitHub Pages 사용 시:
1. 저장소 Settings → Pages → Branch를 이 브랜치(또는 병합 후 main), 폴더 `/ (root)`로 지정.
2. 발급된 주소(`https://<계정>.github.io/<저장소>/`)를 QR코드로 만들어 수업 첫 화면에 게시.

`index.html` 파일만 LMS·웹서버에 올려도 동일하게 작동함.

## 3. 수업 운영 흐름(권장)

1. 수업 전(플립): 해당 월드의 개념 카드·소크라테스 문답 수행.
2. 수업 중: 전광판에서 라이브 퀴즈 → 정답률 70% 미만이면 짝 토론 2분 후 재투표. 팀 활동은 워드클라우드·하브루타 타이머 활용.
3. 수업 후: 퀴즈 아레나·사례 랩·보스전, 출구 성찰 제출.
4. 주 1회: 학생이 `나` 탭의 성과 코드를 LMS 게시판·설문에 제출 → 교수자가 대시보드에 일괄 붙여넣기 → 재지도 개념 확인 → 리그 스냅샷 코드를 학생에게 공유.

## 4. 설계 원칙

- 점수는 정답 수보다 적용·분석·설명·진단 행동에 더 크게 배정(적용·분석 20 XP, 회상·이해 10 XP, 사례 진단 60 XP, 문답 완주 50 XP).
- 과정당화 방지: 이미 맞힌 문항 재풀이 0 XP, 일일 XP 상한 600.
- 낙오자 효과 완화: 전체 공개는 상위 5명뿐이며, 나머지 학생은 자기 순위만 확인. 하위권 이름은 어떤 화면에도 노출하지 않음.
- 앱 점수는 정규 성적에 반영하지 않거나 '참여 완료 여부'로만 반영할 것을 권장함.

## 5. 콘텐츠 수정

`index.html`의 `CONTENT` 영역(`WORLDS`, `CARDS`, `DIALOGUES`, `QUESTIONS`, `CASES`, `HAVRUTA`, `TIMELINE`)만 바꾸면 다른 단원(예: 조직론)으로 재사용할 수 있음.

## 6. 한계

- 성과 코드는 위변조 억제용 체크섬만 있으며 보안 인증은 아님.
- 학생이 브라우저 기록을 지우거나 기기를 바꾸면 학습 기록이 초기화됨. 제출한 성과 코드는 교수자 쪽에 남음.
- '나의 리더십 스타일'은 자체 개발 12문항으로 된 학습용 자기점검이며 표준화 검사가 아님.
